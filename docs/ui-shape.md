# Интерфейс приложения на Mac: экраны

Принципы и визуальные правила: [`design-context.md`](design-context.md). Данные приходят от ядра
приложения (шаг 4 плана), которое опрашивает агентов (`/v1/snapshot`, `/v1/history`) и само
проверяет сайты. Здесь описано, что пользователь видит и что может сделать на каждом экране.

Отдельно: окно «Настройки» (⌘,), листы «Добавить сервер» и «Добавить сайт».

## 1. Строка меню

**Задача:** за секунду ответить «всё ли в порядке» и дать SSH в один клик.

- Значок: символ `server.rack` с маленькой цветной точкой статуса в углу. В норме значок
  монохромный (шаблонный), точка не рисуется. При предупреждении точка жёлтая, при
  критичной проблеме красная. Нет данных дольше 5 минут: значок полупрозрачный.
- Окно по клику (`.menuBarExtraStyle(.window)`, ширина 340):
  - заголовок: общий статус текстом и «опрос 12 с назад», кнопка «Опросить сейчас»;
  - раздел «Проблемы» только если они есть: объект, суть, длительность;
  - разделы «Серверы» и «Сайты»: строка с точкой, именем, одной ключевой цифрой
    (у сервера максимальная из CPU, памяти, диска с подписью; у сайта время ответа);
  - у сервера при наведении кнопка SSH; клик по строке открывает объект в главном окне;
  - внизу «Открыть окно» (⌘0) и «Настройки…», «Выйти».
- Больше 15 объектов: список прокручивается, проблемы всегда сверху.

## 2. Главное окно

### Боковая панель
- **Обзор**, **Проблемы** (бейдж с числом), **Серверы**, **Сайты**, **VPN**, **Журнал**.
- Раздел «Группы»: страны (флаг не используем, только код и название), хостинги, проекты.
- Раздел «Теги»: «прод», «тест» и свои. Выбор группы или тега фильтрует средний столбец.

### Обзор (вместо таблицы и деталей одна страница)
- Строка из четырёх чисел: серверов, сайтов, VPN-клиентов онлайн, активных проблем.
- Активные проблемы списком (как в разделе «Проблемы»), если пусто: одна строка
  «Проблем нет · последняя закончилась 3 ч назад».
- Сетка компактных строк по серверам: имя, мини-график CPU за 1 ч, CPU, память,
  худший диск, сеть ↓↑. Это таблица, а не плитки.
- Сайты: имя, код ответа, время ответа по странам (RU, NL, US) в столбцах, SSL, домен.

### Серверы: таблица
Столбцы: статус, имя, страна, хостинг, CPU %, память %, худший диск %, load 1/5/15,
сеть ↓/↑, аптайм, VPN-клиенты, теги, «обновлено». Сортировка по любому столбцу, выбор колонок.
Значения выше порога окрашены цветом предупреждения, остальные обычным текстом.

### Сервер: детали
- Шапка: имя, адрес, страна и хостинг, статус текстом, аптайм и время загрузки
  («перезагружен 2 дня назад», если загрузка недавняя, это выделено), кнопки
  «SSH» (основная), «Опросить», меню «…» (скопировать адрес, пауза оповещений, изменить, удалить).
- Переключатель периода: 1 ч · 24 ч · 7 д · 30 д (сегментированный контрол в тулбаре).
- Вкладки (`Picker` в виде сегментов над содержимым):
  - **Метрики:** графики CPU (с iowait и steal), памяти и swap, load, сети ↓↑, дисков
    по разделам. Пороги пунктиром.
  - **Сервисы:** PostgreSQL, MySQL и другие из `services`: процесс, порт, задержка, ошибка.
  - **Контейнеры:** таблица `containers`: имя, образ, состояние, health, статус.
  - **VPN:** по каждому контейнеру `vpn`: протокол, запущен, клиентов всего и активных,
    трафик; ниже таблица клиентов (`peers`): имя, последнее рукопожатие, ↓↑.
    Для протоколов без данных о клиентах честная подпись «клиенты не читаются для xray».
  - **Процессы:** топ из `processes`: PID, имя, CPU %, память.
  - **Проверки:** что этот сервер видит из своей страны (`checks`): сайты и соседи.
  - **События:** журнал оповещений этого сервера.
- Ошибки агента (`errors`) показываются узкой полосой под шапкой, не модальным окном.

### Карта
Раздел «Карта» в боковой панели, сразу после «Обзора». Нативная карта MapKit в приглушённом стиле.
- Каждый сервер стоит булавкой в своём городе (координаты задаются при добавлении сервера,
  по умолчанию определяются по IP). Цвет булавки = статус, подпись = имя и главная цифра.
  Несколько серверов в одном городе сливаются в одну булавку с числом.
- Слой «Связи»: линии между серверами по пингу, который агенты делают друг другу, с задержкой
  в мс. Красный пунктир = связи нет. Так видно разницу между «сервер упал» (его не видит никто)
  и «блокировка из страны» (его не видит только одна страна).
- Слой «Сайты»: для выбранного сайта линии от каждой страны проверки с кодом и временем ответа.
- Справа панель выбранной булавки: статус, доступность из каждой страны, последние данные,
  кнопки SSH и «Открыть сервер».
- Фильтр «Все / Только проблемы», кнопки масштаба и «Показать все серверы».
- Новый сервер появляется на карте сразу после добавления.

### Сайты: таблица и детали
- Таблица: статус, адрес, HTTP-код, время ответа (среднее), по странам RU/NL/US,
  SSL (дней), домен (дней), теги.
- Детали: полоса предупреждения (SSL, домен, недоступность), цифры за период
  (доступность в %, среднее время ответа, сроки SSL и домена), полосы доступности по странам
  (клетка = 30 мин: отвечает, медленно, не отвечает, нет данных), график времени ответа с линией
  на страну и подсказкой при наведении, события.

### VPN
Сводка по всем серверам с AmneziaVPN: сервер, протокол, состояние, клиентов
всего/активных, трафик. Выбор строки открывает таблицу клиентов.

### Проблемы и журнал
- **Проблемы:** только активные: важность, объект, суть, с какого времени, длительность,
  «напоминание через 18 мин». Действия: открыть объект, SSH, пауза на 1 ч.
- **Журнал:** все оповещения: время начала и конца, длительность, важность, объект, суть.
  Фильтр по важности и периоду, поиск.

## 3. Добавление объектов

**Добавить сервер** (лист, форма `.grouped`):
1. Имя, адрес (IP или домен), страна, хостинг, теги.
2. SSH: пользователь, порт, способ входа (ключ из `~/.ssh` или пароль); всё в Keychain.
3. Кнопка «Установить агента». Ниже живой журнал шагов (подключение, копирование,
   проверка сумм, установка, получение ключа и отпечатка) с галочками.
4. Вариант «Агент уже установлен»: поля «ключ» и «отпечаток» вручную.

**Добавить сайт:** адрес, из каких стран проверять (чекбоксы по серверам-агентам и «с Mac»),
теги, ожидаемый код ответа.

## 4. Настройки (окно Settings, вкладки)
- **Основные:** интервал опроса, запуск при входе, показывать значок в Dock.
- **Пороги:** CPU, память, диск, длительность для CPU, дни для SSL и домена;
  объект может переопределять их в своём «Изменить».
- **Оповещения:** сколько неудач подряд до оповещения, интервал напоминаний,
  уровни, тихие часы.
- **Данные:** где лежит база, размер, сколько хранить, экспорт для переезда на Mac mini.

## 5. Состояния, которые надо продумать в каждом экране

| Состояние | Как выглядит |
|---|---|
| Первый запуск, объектов нет | В центре окна одна строка и кнопки «Добавить сервер», «Добавить сайт» |
| Данные устарели (Mac спал) | Серый статус «нет данных 2 ч», графики с разрывом, в шапке «догружаю историю…» |
| Агент недоступен | Красный статус, в шапке причина (таймаут, отказ TLS, неверный ключ), последние известные цифры серым |
| Отпечаток сертификата сменился | Критично и отдельное объяснение: возможна подмена, кнопка «Доверять новому отпечатку» с подтверждением |
| Частичные данные | Пустые вкладки пишут почему: «Docker не найден на сервере» |

## 6. Связь с ядром

UI не знает про SQLite и сеть. Он читает наблюдаемый стор ядра (список объектов
с текущим статусом, история метрик за период, активные и прошлые оповещения) и вызывает
действия (опросить, добавить, изменить, пауза). Пока ядра нет, используется мок-стор с
данными, похожими на реальные серверы `wise` (NL, AmneziaVPN) и `wise1` (RU, сайты и PostgreSQL).

## Порядок работы

1. Каркас: окно, боковая панель, таблица серверов, детали сервера с вкладкой «Метрики»,
   строка меню. Всё на моках, собирается на Mac.
2. Остальные вкладки сервера, сайты, VPN, проблемы и журнал.
3. Листы добавления и окно настроек.
4. Подключение к стору ядра вместо моков.
