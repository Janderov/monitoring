# План этапа 1

Источник требований: [`requirements-v1.md`](requirements-v1.md) (версия 1.0, 5 октября 2026). Цель этапа: рабочая
версия для себя за 2–4 недели. Агент на серверах Ubuntu и приложение на Mac.

## Состав репозитория

```
agent/        агент на Go (один бинарный файл, служба systemd)
app/          приложение для macOS на Swift и SwiftUI (появится в шаге 4)
docs/         план, протокол агента, заметки
```

## Принятые решения

| Вопрос | Решение |
|---|---|
| Язык агента | Go, только стандартная библиотека (проще собирать и проверять) |
| Связь Mac и агента | Mac опрашивает агента по HTTPS раз в минуту |
| Защита | секретный ключ в заголовке `Authorization: Bearer`, самоподписанный сертификат, Mac запоминает его отпечаток SHA-256 при добавлении сервера |
| Буфер на агенте | 1440 снимков (24 часа при интервале 1 минута), чтобы Mac подтянул историю после сна |
| AmneziaVPN | установлен приложением AmneziaVPN, то есть работает в Docker; агент читает контейнеры через Docker API |
| SSH | кнопка открывает стандартный Терминал |
| Хранение на Mac | SQLite: поминутно 30 дней, почасовые агрегаты до года |

## Шаги

### Шаг 1. Каркас агента (готово, PR #1)
- конфигурация в `/etc/monitor-agent/config.json`;
- команда `monitor-agent init`: создаёт ключ (или берёт выданный приложением), самоподписанный сертификат и печатает его отпечаток;
- сбор метрик из `/proc`: CPU, память и swap, нагрузка, диски по разделам, сеть (байты и скорость), аптайм и время загрузки;
- список Docker-контейнеров с состоянием (для AmneziaVPN и других сервисов);
- кольцевой буфер на 24 часа;
- HTTPS API: `/v1/health`, `/v1/snapshot`, `/v1/history?since=`;
- unit-файл systemd и скрипт установки;
- тесты на разбор `/proc`, буфер и проверку ключа.

### Шаг 2. Сервисы и проверки на агенте (этот PR)
- AmneziaVPN: число клиентов и трафик через `docker exec ... wg show` в контейнерах `amnezia-awg*` и `amnezia-wireguard`, имена клиентов из `clientsTable`; для остальных протоколов (xray, openvpn) пока только «запущен или нет»;
- PostgreSQL и MySQL: процесс жив, порт отвечает (подключение к самим базам пока не делаем, открытый вопрос 4);
- процессы с наибольшим потреблением;
- проверки сайтов с агента (HTTP-код, время ответа, срок SSL) и пинг соседних серверов, чтобы видеть доступность из каждой страны.

### Шаг 3. Установка одной командой
- сборка бинарного файла под linux/amd64 и linux/arm64 в GitHub Actions, выкладка в релизы;
- команда вида `curl ... | sudo bash -s -- --token <ключ>`, которую генерирует приложение.

### Шаг 4. Приложение на Mac: «мозг»
- проект Swift Package / Xcode, опрос агентов по расписанию, проверка отпечатка сертификата;
- SQLite: хранение снимков, агрегация в почасовые, очистка старых данных;
- проверки сайтов с Mac: HTTP, SSL, срок регистрации домена (WHOIS/RDAP);
- правила оповещений: падение и восстановление, пороги (диск > 90%, CPU > 90% дольше 5 минут, память), SSL и домен за 14 дней, остановка VPN; 2–3 неудачи подряд, напоминание раз в 30 минут, одно сообщение «снова в норме».

### Шаг 5. Приложение на Mac: интерфейс
- значок в строке меню с общим цветом и списком объектов;
- главное окно: дашборд по странам, хостингам и проектам, теги и фильтры;
- карточки сервера и сайта с графиками (Swift Charts), журнал оповещений;
- «Добавить сервер» (генерирует ключ и команду установки), «Добавить сайт»;
- кнопка SSH: открывает Терминал, пароли и ключи хранятся в Keychain;
- уведомления macOS.

### Шаг 6. Проверка на реальных серверах
- установка агента на 1–2 сервера, затем на все;
- подбор порогов и проверка защиты от спама.

## Как проверять

Агент собирается и тестируется здесь (`cd agent && go test ./...`). Приложение на Swift
собирается только на Mac, поэтому его сборку и запуск проверяете вы; для каждого PR с
приложением будет короткая инструкция «что нажать и что должно получиться».
